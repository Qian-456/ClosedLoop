# Mock 支付幂等决策

## 2026-09-16

用户要求：持续改造项目，只通过 PR 交付，并提供手动和面试验收。Agent 发现并实现本修复，用户尚未亲验。

### 问题与流程

预览命令 → 校验 Mock 密码 → 按 execution_id 创建唯一任务 → 一次执行并消费事件 → 保存完整结果 → 后续重复提交重放。文件库存保留真实扣减，演示只覆盖隔离 JSON。

原逻辑把命令留在字典直到完全成功，多次请求可能共用一个执行 ID 并竞争同一队列；失败保留原命令导致成功项被再次执行。

### 方案与取舍

- 每次提交只加互斥锁：理论上避免同时执行，但串行重试仍会重扣，不能满足幂等。
- 每个 execution_id 共享一个 Task 并保留终态：本轮选择，成功/失败/不确定均不重新执行，asyncio.shield 防止客户端取消等待时取消提交。
- 持久数据库状态机：理论上可覆盖进程重启、多副本、事务，但当前 Mock 文件存储没有此能力，本 PR 未实现或实测。

不同支付命令必须使用独立执行作用域，避免内容相同的两个新命令竞争同一个事件队列。结果用 deepcopy 返回，防止调用方改坏缓存。

已验证：同 ID 八次并发库存 3→2；重试仍为2；部分失败重试不重扣；不同 ID 分别执行；取消等待后再次获取结果。18 项相关测试通过，详见 PAYMENT_ACCEPTANCE.md。

限制：单进程内存保留任务，缓存随命令数增长，重启丢失；未证明生产规模吞吐与分布式一致性。若上线多副本或需要持久支付记录，必须改为数据库唯一键、持久状态和事务。未实测方案不得说比当前更快。
